# Roadmap de consolidación · Meridiano Legal v3

## Línea base

- Rama estable: `stable-v3.0.0`
- Canal público: GitHub Pages
- Arquitectura canónica: 8 servicios, 8 productos, 5 planes recurrentes y 6 documentos guiados
- Identidad: marino, marfil, azul y dorado; logotipo angular v3

## Principios para cada iteración

1. No sustituir la identidad ni la arquitectura canónica sin decisión expresa.
2. Trabajar en una rama separada y abrir pull request.
3. Validar HTML, recursos, JavaScript y metadatos antes de fusionar.
4. Mantener la separación entre web pública, demostración estática y plataforma productiva.
5. Evitar afirmaciones, testimonios, cifras o resultados no verificables.
6. Redactar con profundidad jurídica, claridad empresarial y orientación a conversión.

## Iteraciones previstas

### v3.1 · Claridad y conversión

- Explicar para quién es Meridiano.
- Distinguir orientación, servicio, producto y plan.
- Mostrar entregables concretos.
- Explicar cuándo tiene sentido contratar.
- Incorporar preguntas frecuentes y un proceso de contacto más claro.

### v3.2 · Fichas profundas

- Página individual para cada servicio.
- Página individual para cada producto.
- Pregunta ejecutiva, alcance, metodología, entregables, requisitos, exclusiones y siguiente paso.
- Enlaces internos desde necesidades, sectores y perspectivas.

### v3.3 · Autoridad y contenido

- Biblioteca de perspectivas jurídicas.
- Artículos por contratos, IA, propiedad intelectual, proyectos regulados y Legal Operations.
- Perfil profesional y metodología de trabajo.
- Metadatos sociales y estructura SEO por página.

### v3.4 · Experiencia y conversión

- Asistente de selección de modalidad.
- Formulario de calificación inicial más estructurado.
- Comparador de productos y planes.
- Mejoras de accesibilidad, rendimiento y navegación móvil.

### v3.5 · Meridiano Empresas

- Coherencia visual completa con la web pública.
- Recorridos por perfil.
- Mejoras en solicitudes, expedientes, obligaciones, documentos y riesgos.
- Límites visibles de la demostración y preparación para arquitectura productiva.

## Criterios para considerar una versión estable

- GitHub Actions completamente aprobado.
- Sin rutas, anclas o recursos rotos.
- Responsive en escritorio, tableta y móvil.
- Contenido coherente con la arquitectura canónica.
- Avisos legales y límites demostrativos visibles.
- Rama estable creada después de la publicación.
